# Lumi — актуальный контекст

Срез: 2026-11-16. Рабочая копия: `/home/kesh/MyCode/lumi`.
Этот документ фиксирует наблюдения; [SPEC.md](SPEC.md) отделяет проект будущих требований от реализации.

## Продуктовый результат

Lumi — универсальный CLI и skill для исследовательских агентов. Агент получает вопрос,
изучает контекст и уже собранную библиотеку, находит полезные источники, объясняет их
связь с исследованием и помогает надёжно прочитать текст. Результат доступен в чате;
по необходимости агент оформляет документ с подборкой и очередью чтения.

Поиск — основа первой версии. Чтение литературы, включая извлечённый текст сканов,
входит в неё. Ссылки на надёжные архивы и сайты с данными могут быть поисковыми находками;
самостоятельная проверка датасетов, пробы и матрица пригодности отложены целиком.
В целевой версии нет собственного слоя фактов и позиций.

Диплом Марка — бенчмарк, а не зашитая тема продукта. Его вопрос об организационных
характеристиках китайских организаций и genAI в 2018–2025 хранится в исследовательском
контексте. Общие эвристики и подходы универсальны. EN/ZH/RU одинаково входят в приёмку.

## Принятые решения

- Агент выбирает масштаб работы и эвристики по задаче; одинаковые численные потолки из опросника отклонены комментарием O2.
- Агент сначала знакомится с уже собранным, затем предлагает план и ищет дополнения. Технические «ветви» пользователь задавать не обязан.
- Один просмотр пакета для получения текстов за раунд; весь пакет ранжируется, короткий список читается.
- Инструмент работает с разными агентными средами; контракт — короткий skill и JSON основных команд.
- Поиск, данные и чтение — части одного продукта. Отсрочка режима данных не превращает его в чужую задачу навсегда.

## Что есть в коде

- Единая точка входа `lumi.cli:main`; установщик, настройка ключей и локальная диагностика.
- Поиск по научным API с пагинацией до заданного `--limit`; получение прямых цитирующих и цитируемых соседей одной работы. Ошибка следующей страницы сохраняет уже полученные результаты и даёт код 1.
- Сохранение источников, извлечение страниц, поиск по тексту и проверка дословных цитат.
- Слой `literature/`: ключи и имена папок, проверка, план нормализации и явное применение.
- Основные команды теперь работают на месте с `literature/` + `research/`, включая
  структуру диплома. Корень определяется из вложенных папок; `add` не создаёт вторую
  библиотеку, повтор сохраняет README, заметки и извлечённый текст. Общий парсер учитывает
  выбранную версию PDF и готовый OCR; старый индекс и записи знания не перезаписываются.
- Удалены слой фактов/позиций, встроенные воркеры, периферийные команды ORCID/PatentsView/World Bank и старый мигратор.
- Единственный парсер и FTS-индекс находятся в `lumi/library.py`; команды `parse` и `lookup` используют их, в том числе с явным `--library`.
- Удалены генератор `FIELD.md` и дубли `library parse`/`library lookup`. `field` показывает кандидатов;
  `field refs` выводит все недостающие ссылки без скрытого среза, с явным `--min` (по умолчанию 1).
  Частичный результат сохраняет полученные метаданные и возвращает 1. Старые отчёты не меняются.
- Вопросы сохраняют ID и текст; неиспользуемое поле `keywords` удалено из модели и нового шаблона.
  Старые строки вопросов читаются без переписывания файлов. Контекст нового проекта универсален.
- `parse` помечает извлечение с пустыми страницами как `partial`, перечисляет их и возвращает 1. Неполная повторная попытка сохраняет прежний текст. Это проверка покрытия текстовым слоем, не оценка точности OCR.
- `add` возвращает 1, если сохранены только метаданные или неполный текст; отказ поиска открытой копии отличается от отсутствия копии. Новые карточки ссылаются на текущие статусы в метаданных.
- Поиск по китайским фрагментам использует буквальное вхождение внутри страниц; обычный FTS сохраняется для остальных слов и `--raw`.
- Работы CORE, Lens и Semantic Scholar без DOI сохраняются по нативному ID с исходными метаданными провайдера. Наличие записи OpenAlex для добавления не требуется.
- `library check` не обходит `research/knowledge/` и не требует личных заметок или AI-отчёта.
- `init` создаёт `literature/` + `research/` и копирует короткий skill. `--context` заполняет
  `CONTEXT.md`, новое `lumi.json` хранит имя. Привязанный к машине `./lumi` больше не создаётся;
  существующие файлы и их права сохраняются.
- Локальные команды чтения и проверки работают независимо от API-настроек.
- Поиск сохраняет ID каждого возвращённого результата в журнале, включая повторные находки
  и статьи в библиотеке; событие содержит запрос, провайдера, вопрос и время. Старые события не переписываются.
- Изменения кандидатов проходят под файловой блокировкой с атомарной заменой, записи без
  изменений пропускаются. Параллельные добавления в журнал также защищены блокировкой.
- Общий resolver `Library.find` обслуживает ID, DOI, ключ и «Автор Год»; отдельный адаптер
  библиотеки под Project удалён. `add` обновляет каталог один раз, индекс — при следующем
  поиске, если изменились страницы.
- Удалены `engine.index.build`, замена снимка кандидатов через `save_candidates` и флаг
  `pages --detect`. `pages` показывает и задаёт номера; извлечение запускается через `parse`.
  Пустой `lumi` всегда показывает справку, настройка запускается через `lumi setup`.
- Нормализация сохраняет имена DOI/arXiv/local-папок при появлении OpenAlex ID; поиск
  использует ID из метаданных. Поддержка старых папок `W…` сохранена.
- Чтение и валидация метаданных общие для библиотеки, команд статей, поиска и выбора PDF.
  Актуальный статус текста вычисляется отдельно по страницам.
- Повреждённые метаданные и сбои поиска цитат возвращают явную ошибку; диагностика библиотеки
  продолжает проверять здоровые папки. Битая запись ответа API не скрывает остальные ссылки.
- `AGENTS.md` ссылается на skill; `CLAUDE.md` подключает `AGENTS.md` одной строкой. Обязательных ритуалов завершения сессии нет.

## Чего пока нет как законченного сценария

- Рекурсивного обхода с сохраняемой очередью, всеми путями происхождения и возобновлением. Пагинация отдельных запросов уже есть; курсоры пока не сохраняются между запусками.
- Доказательства покрытия поля. Число новых находок в журнале поиска не является оценкой насыщения.
- Отдельного режима проверки пригодности датасетов; по решению P3 он не входит в текущий выпуск.
- Проверенного полного сценария чтения PDF-сканов на всех трёх языках.
- Единого структурированного вывода основных команд для агента.

`citations` получает цитирующие работы с пагинацией до заданного `--limit`.
Исходящие ID обрабатываются все, затем выводится до `--limit` самых цитируемых.
Количество полученных и показанных работ видно; недостающие записи API дают частичный результат.
Это не обход до второго поколения.
Частоты ссылок в `fetch_refs` не являются полноценной реализацией всех видов сходства статей.

## Техническое состояние

Старые рабочие каталоги объединены в эту копию; их резервные архивы сохранены вне репозитория.
В рабочем дереве уже выполнена реорганизация: CLI находится в `lumi/`, документы v1 —
в `docs/`, прежние планы — в `docs/archive/`. История и локальные изменения не сбрасывались.
До текущих исправлений версия 0.2.0 проходила 45 тестов; пакет был проверен в отдельном окружении,
а на копии диплома — 63 записи, цитаты в 53 статьях с текстом, обычный PDF и готовая OCR-копия.
После аудита добавлены регрессии пагинации, ошибок и частичных результатов, нативных ID,
EN/RU/ZH-поиска и запрета чтения старого знания. До упрощения интерфейса проходили 92 теста, включая реальный
трёхстраничный PDF с двумя пустыми страницами через Poppler. Контракты API сверены с документацией;
автотесты коннекторов используют подменённые ответы. Это не проверка живых API или качества исследования.

После первого упрощения интерфейса проходили 105 тестов, включая прямую библиотеку без проекта,
ссылки «Автор Год», полный вывод ссылок и сохранение частичного кэша при сбое API.

После второго прохода очистки проходят 139 тестов, включая одновременную запись из четырёх
процессов, происхождение повторных находок, повреждённые метаданные и локальную работу
с невалидным файлом API-настроек.

Установленная через uv команда — копия пакета на момент последней установки. После изменений
кода её нужно обновлять; текущее устройство проверяется из этого checkout.

## Что остаётся открытым

P7: конкретный живой пилот не выбран; пользователь не обязан выбирать между одной и
восемью «ветвями». Предложить контрольный вопрос и критерий полезности обычными словами.
O5: срок включения сходства списков литературы не выбран; конкретные методы остаются
техническим предметом проектирования и испытания. O6 неприменим из-за отсрочки режима данных.

Ближайшая работа описана в [PLAN.md](PLAN.md): определить JSON-контракт, сделать надёжный поиск и чтение. Удаление старых пользовательских
записей не следует из отказа от старой модели продукта.
