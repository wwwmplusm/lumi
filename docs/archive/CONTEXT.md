## Цель

Работать так: пользователь запускает Claude Code в `diplom/` и задаёт вопросы; Claude помогает курировать исследование на основе данных (искать, читать, отвечать с проверенными цитатами, предлагать следующие шаги). Пользователь владеет вопросами, позициями и выводами.

Принципы:
- Без сторонних сервисов (Zotero, NotebookLM и т.п.): свои локальные файлы + CLI + git.
- **LLM может ошибаться, код — нет.** Всё, что должно быть надёжным (цитата есть на странице, страница верна, число в цитате), проверяет код.
- Знание динамично: факты + позиции, опирающиеся на посылки; позиции меняются, история сохраняется.

## Что есть сейчас (кратко, подробно — PIPELINE_current.md)

- `research/library.py` (~1170 строк): поиск (OpenAlex, arXiv, Crossref…), `add`, разбор PDF по страницам, FTS5-поиск (`lookup`, `show`), извлечение claims изолированными воркерами (`claude -p`, Sonnet) с проверкой цитат кодом, разметка own/cited/reported, `lint` (числа в утверждении, которых нет в цитате), пары/`link`/`review`/`propagate`, `map`, `gaps`, `audit`.
- Данные: 24 статьи (13 с полным текстом, 340 стр.), 240 claims, 637 candidate-рёбер (ни одно не подтверждено). 22 теста.
- Ночной прогон 2026-10-09→10: отчёт в `diplom/sessions/2026-10-09-night.md`.

## Решения, принятые в разговоре 2026-10-10

1. **Интерфейс = Claude Code в чате**, а `library.py` — инструменты Claude, не пользователя.
2. **Заморозить**: пары (`candidates`/`link`/`review`), автоматический граф claim↔claim, ночные прогоны как основной сценарий. Причина: 83% пар — шум; люди связывают знание по вопросу и во время чтения, а не перебором (см. гайды по литературе: социтирование + заметки + тезис/антитезис/синтез).
3. **NotebookLM не используем**: не «тупой RAG», но не проверяет верность пересказа, не различает своё/цитируемое, не воспроизводим.
4. Идею посылок и `propagate` сохранить, но применить к **позициям пользователя**, а не к парам выписок.

## Целевая архитектура (по наброску пользователя)

```
diplom/
├── CONTEXT.md        context: тема, вопросы, где мы сейчас (Claude читает первым)
├── MAP.md            map (index): генерируется кодом
├── sources/
│   ├── papers/       PDF + текст по страницам (+ напечатанные номера страниц)
│   └── datasets/     данные + происхождение
├── knowledge/
│   ├── claims.jsonl  факты из источников, цитата проверена кодом
│   └── beliefs.md    позиции: утверждение → посылки (C…, N…) → против → история версий
├── notes/            заметки пользователя по датам
├── drafts/           текст диплома, ссылается на B…/C…
└── sessions/         журнал сессий + search_log.jsonl (+ git = история изменений)
```

Иерархия: источники → факты (claims) → позиции (beliefs) → черновики. Каждый уровень ссылается только вниз; из любой фразы черновика можно дойти до страницы статьи.

Формат позиции (черновик):
```
B3: «Санкции сместили китайский ИИ к эффективным методам»  (уверенность: средняя)
  посылки: C0166, C0128, N-2026-10-12
  против:  C0090
  история: v1 2026-10-10 «санкции душат» → v2 2026-10-12, причина: C0166
```
Позиции не затираются: старая версия → «заменена» с причиной. Если посылка опровергнута → позиция помечается «пересмотреть».

Workflow сессии:
- **старт**: Claude читает CONTEXT.md + последнюю сессию → говорит, где мы и что висит;
- **в работе**: статья → sources + claims; мысль → notes; сдвиг позиции → новая версия в beliefs;
- **конец**: Claude пишет `sessions/<дата>.md`, код пересобирает MAP.md, git commit.

## Критичные проблемы кода (аудит 2026-10-10)

1. Страницы = индексы PDF, не напечатанные номера журнала → неверные ссылки в дипломе.
2. Нет `check` для произвольной цитаты → цитаты Claude в чате не проверяются кодом.
3. Проверка цитат хрупкая: точное совпадение, ≥20 символов, «…» не проходит.
4. Код не проверяет, что утверждение следует из цитаты (аудит: 7/40 преувеличено/не подтверждено).

Важные, но не критичные: `add` не ловит обрезанные PDF (только заголовок `%PDF-`) и не делает parse; INDEX.md смотрит на устаревший `paper.txt`; 11/24 статей только метаданные; нет подсчёта социтирования и критерия насыщения; нет склейки дублей (препринт/журнал); нет журнала сессий; нет генерации списка литературы (ГОСТ); сетевая часть без тестов.

## План (исходный порядок; пп. 1–3 сделаны)

1. `check` — проверка цитат (лестница FOUND / FOUND* / SEGMENTS / DRIFT / ABSENT), см. RESEARCH_FINDINGS.md.
2. Напечатанные номера страниц (qpdf PageLabels → колонтитулы + OpenAlex first_page → метаданные → вручную).
3. Перестановка папок под целевую архитектуру, CONTEXT.md в `diplom/`, `beliefs.md`, журнал сессий, новый CLAUDE.md (роль куратора).
4. Правило «цитата только с [W… p.N] и после check» + Stop hook (**только после явного согласия пользователя** — меняет настройки).
5. Расширенный `lint` (оговорки, причинность, кванторы, новые слова) → изолированный воркер-судья «цитата ↔ утверждение».
6. Позже: подсчёт социтирования + критерий насыщения, склейка дублей, список литературы.
