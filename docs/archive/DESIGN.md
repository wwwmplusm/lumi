# Lumi v2 — system design

Дата: 2026-10-28. Статус: проект, код не менялся. Источники: код `engine/`, `SCHEMA.md`, `CONTEXT.md`, `RESEARCH_FINDINGS.md`, `thoughts.md`, состояние `diplom/`, [chinese_russian_sources_research.md](chinese_russian_sources_research.md) и три независимые перепроверки субагентами (раздел 7.2 и приложение).

Обозначения: **[факт]** — проверено кодом, файлом или живым запросом 2026-10-28; **[док]** — по документации/README, не испытано; **[допущение]** — проверить до реализации.

## 1. Цель и границы

Библиотека, которая экономит токены, упрощает повторную работу с источниками и сохраняет проверяемый путь *рукопись → место → выписка → страница/координаты → неизменяемый оригинал*. Интерфейс: CLI + переносимый skill (Claude Code, Codex, любой агент с shell); MCP — тонкий опциональный адаптер.

**MVP:** хранилище оригиналов по хешу; работы и версии с происхождением; извлечение страниц/меток/координат; карточки и проверенные выписки; ступенчатый поиск; коннекторы с журналом запросов, кандидатов и отказов; граф цитирований и версий с заглушками; исследовательские заходы; насыщение маршрута; `check` (дословность) и отдельный статус поддержки; учёт источников по рукописям.

**Не делаем:** GUI, TMS, claims/beliefs, собственный агентный runtime и автоворкеры, эмбеддинги, граф claim↔claim, форматирование ГОСТ (только экспорт CSL-JSON/BibTeX), массовое зеркалирование баз, сбор с сайтов, запрещающих автоматизацию.

## 3. Build vs reuse

| Вариант | Решение | Почему |
|---|---|---|
| Zotero + Better BibTeX / zotero-mcp (MIT) | не основа; взять формат citekey, экспорт BibTeX/CSL | нужен запущенный GUI; нет журнала поиска, насыщения, проверки цитат, учёта по рукописям |
| PaperQA2 (Apache-2.0) | не брать; взять идею «дешёвый поиск → контекст» | свой агентный runtime, нужен LLM через API |
| GROBID (Apache-2.0) | опционально (Docker) | список литературы и контексты цитат, когда API ссылок не дают |
| PyMuPDF / pymupdf4llm | не по умолчанию | AGPL-3.0 [факт]; для личного использования допустимо, но ядро держим без copyleft |
| **pypdfium2** (Apache-2.0/BSD-3) | **основной экстрактор** | текст, bbox символов [док]; метки страниц через pdfium [допущение]; убирает qpdf |
| **rapidfuzz** (MIT) | **берём** | `partial_ratio_alignment` для нечёткого этапа `check` |
| Готовые MCP для CNKI/AMiner/Wanfang | только аудит, не зависимость | неофициальные, частью без лицензии, браузерная автоматизация (раздел 7) |

Строим сами только то, чего нет готового: модель хранения с происхождением, журнал поиска/решений, насыщение, учёт по рукописям, обвязку проверки.

## 4. Данные и файлы

Источник правды — файлы в git; SQLite — пересобираемый кеш.

```
<project>/
  lumi.toml                        коннекторы (ключи только из env), пороги, бюджеты
  library/
    blobs/sha256/ab/<sha>.pdf      оригиналы, 0444, имя = хеш; никогда не меняются
    works/<work_id>.json           работа: ids, citekey, метаданные, версии, provenance полей
    extract/<sha>.<extractor_v>.jsonl.gz   страницы: index, label, text, words[[x0,y0,x1,y1,start,end]]
    cards/<citekey>.md             карточка
    excerpts.jsonl                 проверенные выписки (append-only)
    graph.jsonl                    cites / version_of / same_as / translation_of (append-only)
  discovery/
    queries.jsonl                  запрос, коннектор, версия API, язык, фильтры, total_hits, received, статус, хеш ответа, run_id
    candidates.jsonl               события: seen → accepted | rejected(reason) | deferred
    http/<sha>.json.gz             сырые ответы — доказательство происхождения
  runs/<date>-<slug>/              run.json, answer-v1.md, gaps.md, answer-v2.md
  manuscripts/<name>/              manuscript.json (путь к рукописи, .bib), sources.jsonl
  notes/                           ПОЛЬЗОВАТЕЛЬ — агент только читает
  agent/                           АГЕНТ — sessions/, summaries/, log.jsonl
  .cache/index.sqlite              FTS5 + таблицы графа (вне git)
```

**Work:** `work_id` (ULID, локальный, независим от OpenAlex), `citekey` (назначается один раз, старые — в `aliases`), `ids` {doi, openalex, arxiv, pmid, s2, aminer, wanfang, elibrary, doaj, oai:<repo>:<id>, …}, `titles[]` с языком (оригинал + перевод), `status` stub|metadata|abstract|fulltext, `versions[]` {label, blob_sha, source_url, retrieved_at, connector, http_ref, license, `access`: metadata|abstract|fragment|fulltext}, `meta_provenance` (поле → какой ответ).

**Дедупликация:** файлы — sha256; работы — нормализованный DOI, arXiv без версии, внешние ID. Название+автор+год (rapidfuzz ≥95, с транслитерацией) только *предлагает* `lumi merge`; перевод, препринт и журнальная версия автоматически не склеиваются — это рёбра `translation_of`/`version_of`. Составные записи с несколькими DOI (OpenAIRE) не склеивать сами.

**Excerpt:** citekey, blob_sha, extractor_v, pdf_page, page_label, char_span, bboxes, quote, match+score, verified_at. **Карточка:** frontmatter `basis` (fulltext sha | abstract), `written_by/at`; разделы «Данные», «Методология», «Результаты», «Ограничения», у каждого пункта страница; это путеводитель, не источник цитат.

**Рукопись (`sources.jsonl`):** citekey, status planned|cited|dropped, `locations[]` (файл, строка, хеш абзаца, локатор «с. N», текст), `quote_check`, `support` unchecked|supported|partial|unsupported (+ кто/когда/почему).

**Заметки:** запрет записи в `notes/` = правило skill + `lumi lint` (падает, если коммит агента трогает `notes/`) + по желанию deny-правило Claude Code (ставит пользователь).

## 5. Алгоритмы

**Дословная проверка (`check`):** нормализация с картой смещений → точно: страница → ±1 → документ → библиотека (ловит не ту статью) → SEGMENTS вокруг «…» по порядку → `partial_ratio_alignment` по окнам-кандидатам из FTS + пословный diff → <100% = DRIFT, не принимается, показан настоящий текст. Цифры, отрицания, имена — только точно; для цитат <40 символов нечёткий этап выключен. Результат: вердикт, span, страница, bbox. Для китайского — нормализация полной/половинной ширины и посимвольное (не пословное) выравнивание.

**Поддержка контекстом** — отдельно: L0 код (`lint`: числа, оговорки, причинность, кванторы, новые имена); L1 агент сессии по skill смотрит `lumi context` и записывает `support` с обоснованием. Сторонние LLM API не вызываются; `claude -p` — опция `--worker`, выключена.

**Насыщение маршрута:** раунд k = связи (refs + cited-by) принятых работ, минус уже виденное; `new_unique_k` — прошедшие отбор (причины в журнале). «Насыщено» только при `new_unique=0` два раунда подряд **и** покрытии данными о ссылках ≥90% работ маршрута; иначе `unknown (нет ссылок у N)`. Пустой или ошибочный ответ — `no_data`, не ноль. Это насыщение маршрута, а не полнота поля. Для русских/китайских работ ссылки часто недоступны — `unknown` будет нормой, и это правильно (раздел 7).

**Ступенчатый поиск:** `find` (строка на работу) → `card` (≤250 слов) → `grep` (фрагмент ±1 предложение) → `context` (окно страниц). Везде `--json`, `--limit`.

## 6. Интерфейсы

**CLI** (`--json` везде, атомарная запись temp→rename):
```
lumi init | status | doctor                    зависимости, ключи, бюджеты, целостность
lumi search <connector> "<q>" [--lang ru|zh|en] [--run R]
lumi candidates [--run R] | accept <id> | reject <id> --reason "…"
lumi add <doi|id|url|pdf> | attach <key> <pdf> | fetch-fulltext <key>
lumi import <bibtex|ris|csl|oai-dump>          разрешённые экспорты (ИСТИНА, eLIBRARY, CNKI-экспорт вручную)
lumi refs <key> | cited-by <key> | merge <a> <b> --reason
lumi find | card <key> [--write] | grep "<q>" | context <key> --page N
lumi check --text FILE|- | excerpt add <key> "<quote>" --page N
lumi support <excerpt|location> --verdict … --note …
lumi run new "<вопрос>" | round <R> | saturation <R> | show <R>
lumi ms add <name> <file> --bib F | scan | plan <key> | report
lumi export bib|csl | reverify | lint | rebuild-index | verify-blobs
```

**Skill** `skills/lumi/SKILL.md`: workflows (раздел 8), ступенчатое чтение, «цитата только после `check`», запрет записи в `notes/`, формат `[Автор Год, с. N]`, правила коннекторов (не обходить ограничения, бюджет платных вызовов). [допущение] Codex читает SKILL.md так же — проверить в фазе 0.

**MCP** (последняя фаза, ≈150 строк): `find`, `card`, `grep`, `context`, `check`, `run_show`, `ms_report`; только чтение + check. [допущение] веб-клиентам нужен HTTP/туннель.

## 7. Коннекторы

Принципы: поиск отделён от получения текста; каждая выдача → `queries` + `candidates`, а не прямо в библиотеку; число совпадений базы хранится отдельно от числа полученных; статусы metadata/abstract/fragment/fulltext различаются; HTTP 200 ≠ релевантность или полнота; не обходить ограничения; TLS-проверку не отключать; ключи — только env; платные вызовы — с явным бюджетом в `lumi.toml`. Подписка Claude сторонние API не оплачивает.

### 7.4 Последствия для дизайна

1. **Независимый `work_id`** — обязателен (P0 исследования совпадает с разделом 4): у многих русских/китайских работ нет DOI и OpenAlex ID.
2. **Граф для нелатинских работ:** из проверенных открытых источников списки литературы дают только OpenAlex/Crossref (для работ с DOI), AMiner (платно) и eLIBRARY (по договору); DOAJ/OpenAIRE/OAI — нет. Значит, для таких работ основной путь — извлечь список литературы из PDF (GROBID опционально) и разрешать ссылки как заглушки; насыщение будет честно `unknown`.
3. **Язык** хранить на уровне названия/аннотации с `lang_source` (поле статьи | журнал | детектор); язык журнала не считать языком статьи. [док] OpenAlex занижает число русскоязычных статей (Céspedes et al., arXiv 2409.10633) — фильтр по языку OpenAlex не использовать как критерий отбора.
4. **Покрытие:** OpenAlex индексирует почти все журналы DOAJ (QSS 2025) — DOAJ даёт добавочную ценность в основном за счёт аннотаций/ссылок на текст и non-DOI-статей; это проверяется контрольным набором до расширения.
5. **Транслитерация** в дедупликации авторов (кириллица, пиньинь) и хранение оригинальных и переведённых названий.

## 8. Workflows

1. **Заход:** `run new` → поиск по библиотеке → `answer-v1.md` → `check` → `gaps.md` (пробелы, альтернативные объяснения) → запросы (термины из найденного; на нужных языках) → кандидаты accept/reject с причиной → `add`, текст → карточки, выписки → `answer-v2.md` → `check`; при цитатном маршруте — `round` до насыщения или `unknown`.
2. **Библиотека:** ступенчатое чтение; карточка пишется при первом чтении и переиспользуется.
3. **Рукопись:** `ms scan` (pandoc `[@key, p. N]`, `\cite{}`, `[Автор Год, с. N]`) → сверка с .bib (цитируется без bib / bib без цитирования / запланировано без цитирования / неизвестный ключ) → `check` → `support` → `report`.
4. **Конец сессии:** `agent/sessions/<дата>.md` со ссылками на run, excerpts, queries; git commit.

## 10. Ошибки и восстановление

- Блобы: temp → fsync → rename → chmod 444; `verify-blobs` пересчитывает хеши, несовпадение — ошибка, перезаписи нет.
- JSONL только дописывается; битая последняя строка — `lint --repair` с подтверждением. Индекс пересобирается из файлов.
- Сеть: backoff на 429/5xx; сырой ответ кешируется до разбора; отказ = `error`/`no_data`, не ноль. Ответ «нет доступа» с HTTP 200 (ChinaXiv, BASE) распознаётся по телу как `denied`.
- Бюджет: платный коннектор останавливается при достижении лимита из `lumi.toml`; расход виден в `doctor`.
- Битый/обрезанный PDF → `damaged`, не участвует в `check`.
- Метки страниц: pdfium label → колонтитулы → метаданные → `manual`; неподтверждённое печатается как «PDF-с. N».
- Идемпотентность: повторный `add` ничего не меняет, кроме события.

## 11. Тесты и приёмка

Тесты: PDF-фикстуры (две колонки, колонтитул, PageLabels, скан, обрезанный, китайский текст); golden-цитаты (точная, через разрыв, с «…», изменённая цифра → DRIFT, перефраз, не та статья); записанные ответы коннекторов, включая `denied`-с-200 и пустые; насыщение при 50% покрытия → `unknown`; рукопись с четырьмя типами расхождений; property: байты `blobs/` и `notes/` не меняются ни одной командой.

Приёмка:
1. Хеши `blobs/` и `notes/` до и после полного прогона совпадают.
2. Golden-набор: 100% ожидаемых вердиктов, 0 ложных FOUND.
3. От любого места рукописи `ms report` доходит до blob sha + страница + bbox.
4. Повторный заход по тому же вопросу — ≤⅓ токенов первого (длина вывода CLI на `diplom`).
5. Коннекторы: фиксированный набор ru/zh/en запросов и известных статей; отчёт по добавочным релевантным находкам, дублям, доступности разрешённого текста, задержке, стоимости, сбоям. Новый коннектор подключается только при измеренной добавочной ценности.
6. Миграция `diplom`: 49/49 записей, все PDF с совпадающими хешами; каждая старая цитата claim — либо excerpt, либо в `failed_reverify` с причиной.
