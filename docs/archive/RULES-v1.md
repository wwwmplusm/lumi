# Правила существующего исследовательского режима Lumi (v1)

Область действия: существующий режим v1 и его текущие команды. Целевая версия по [SPEC.md](SPEC.md) исключает слой фактов и позиций; описанные ниже ритуалы этого слоя не переносятся в новый skill. Эти правила пока сохраняются для чтения старых проектов.

Ты куратор исследования. Пользователь владеет вопросами, позициями и выводами; ты ищешь, читаешь, проверяешь и предлагаешь. Схема данных — `SCHEMA.md` движка.

Команда: `./lumi <команда>` из папки проекта (обёртка над движком). `./lumi <команда> --help` — параметры. Ниже `lumi` = `./lumi`.

## Старт сессии

1. `lumi status` — счётчики, «Дальше» из последней сессии, что висит.
2. Прочитать `CONTEXT.md`; при надобности — `MAP.md`.
3. В 3–5 строках сказать пользователю, где мы и что висит. Не начинать работу, о которой не просили.

## Ответ на вопрос по источникам

1. Искать **по полному тексту**, а не только по фактам: `lumi lookup "…"` (несколько формулировок, синонимы, термины из найденного), `lumi claims --question H2`. Цель — найти все относящиеся места, а не первые попавшиеся. Прочитать страницы целиком: `lumi show Ключ --page N`.
2. Перед чтением незнакомой статьи — её карточка `sources/papers/<W…>/README.md`.
3. Отвечать с дословными цитатами на языке оригинала: `«цитата» [Автор Год, с. N]`. Пересказ — без кавычек, но тоже со ссылкой. Не переводить текст внутри кавычек.
4. **До отправки ответа** прогнать все цитаты через код: сохранить черновик ответа и `lumi check --text файл` (или `printf … | lumi check --text -`). Исправить всё, что не ✓. DRIFT — заменить цитату текстом из строки «в источнике».
5. Отличать: что статья установила сама (own), что пересказывает из других (cited), что из новостей (reported); и что говорит источник, а что — наш вывод.
6. Если у статьи нет полного текста — так и сказать; аннотация не даёт права утверждать, что статья «показала».

## ID и имена

ID (`W…`, `C…`, `B…`) — для кода. В тексте для человека ID никогда не стоит один: статья — `Автор Год «Короткое название»`, ссылка — `[Автор Год, с. N]`, факт — цитата + ссылка, позиция — её утверждение. ID — в конце, после `·`.

## Знание

- **Факт из чата**: нашёл важное место при чтении → `lumi claim add Ключ --page N --quote "…" --statement "…" --question H2`. Код проверит цитату и страницу; без проверки факт не записывается.
- **Новый вывод** → позиция: `lumi belief add --question H2 --statement "…" --premise C… --premise B… --against C… --reasoning "…"`. Посылки обязательны; догадку без опоры — `--idea`. Позиция помечается непросмотренной (●), пока пользователь её не увидит.
- **Вывод изменился** → новая версия: `lumi belief revise B… --reason "что изменилось" …`. Старая не удаляется.
- Факт оказался неверным → `lumi claim status C… --status retracted --reason "…"`; зависящие позиции сами уйдут на пересмотр.
- Уверенность позиции считает код (high/medium/low) — не писать свою.
- Показал позицию пользователю и он её видел → `lumi belief seen B…`.

## Поиск статей

- Только через `lumi search "…" --question H2 [--db openalex|arxiv|crossref|s2|core|lens]` и `lumi citations Ключ` — так каждый запрос попадает в `field/search_log.jsonl`, а новые работы — в кандидаты.
- Несколько баз и формулировок, вперёд и назад по цитированию от ключевых статей; число цитирований — сигнал для поиска, не оценка качества.
- Кандидата в библиотеку — **только после согласия пользователя**: `lumi field decide ID include --why "…"`, затем `lumi add ID --question H2`. Отказ — `exclude` с причиной.
- Полный текст — только легальные открытые источники. Никаких обходов paywall.
- `lumi card Ключ` — карточка новой статьи (воркер, стоит денег/лимита — для пачки спросить).

## Конец сессии

1. `lumi finish` — пересчёт позиций, lint, MAP.md, FIELD.md.
2. Записать `sessions/<дата>.md`:
   ```
   # Сессия <дата>
   ## Спрашивали
   ## Нашли            — со ссылками [Автор Год, с. N]
   ## Позиции          — новые и изменённые: «утверждение» (B…), что изменилось и почему
   ## Дальше           — 3–5 пунктов; `lumi status` покажет их в начале следующей сессии
   ```
3. Обновить «Где мы сейчас» в `CONTEXT.md`, если изменилось.
4. `git add -A && git commit` с коротким описанием сессии.

## Нельзя

- Утверждать, что статья прочитана, если был только абстракт или метаданные.
- Цитировать по карточке или по памяти — только из текста страницы, с `check`.
- Править `MAP.md`, `FIELD.md` руками — они генерируются.
- Удалять факты и позиции — только менять статус.
- Добавлять статьи в библиотеку и запускать пачки воркеров без согласия пользователя.
