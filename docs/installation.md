# Установка Lumi

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Из скачанного репозитория:

```sh
sh install.sh
```

Скрипт устанавливает пакет `lumi-cli` в изолированное окружение uv, создаёт
команду `lumi` и запускает мастер. Репозиторий после установки не требуется.
Если каталог команд uv отсутствует в PATH, выполните `uv tool update-shell`
и откройте новый терминал. Обновление из новой версии репозитория — той же командой.

Альтернативно: `uv tool install .`, затем `lumi setup`.
Запуск `lumi` без аргументов в терминале также открывает мастер.

```sh
lumi setup              # подключить или изменить API
lumi doctor             # зависимости и наличие настроек; без сетевых запросов
lumi doctor --online    # по одному запросу к API; расходует квоты провайдеров
lumi init ./research --name "Моё исследование"
```

Мастер предлагает OpenAlex, Semantic Scholar, Unpaywall, CORE и Lens,
показывает ссылки для получения доступа. Сами ключи нужно получить
в аккаунтах сервисов; мастер не создаёт аккаунты и не оформляет подписки.
arXiv и Crossref не требуют ключей.
Enter сохраняет текущее значение или пропускает сервис, `-` удаляет сохранённую настройку.
Semantic Scholar можно вызывать без ключа; доступ и лимиты определяет сервис.
Unpaywall требует email, а не токен.

Настройки сохраняются в `$XDG_CONFIG_HOME/lumi/credentials.json`
(по умолчанию `~/.config/lumi/credentials.json`), вне исследовательских проектов.
Это **незашифрованный локальный файл с правами 600**. Он загружается при запуске CLI;
переменные окружения имеют приоритет. Ключи не выводятся в диагностике.
Не добавляйте файл настроек в git. Для автоматической установки используйте
`sh install.sh --non-interactive`: сохраняются только уже доступные переменные
окружения и существующие настройки; отсутствующие ключи остаются ненастроенными.
Переменные: `OPENALEX_API_KEY`, `S2_API_KEY`, `UNPAYWALL_EMAIL`, `CORE_API_KEY`,
`LENS_TOKEN`. Старые неиспользуемые ключи в файле сохраняются, но не загружаются в окружение.

Системные PDF-утилиты устанавливаются отдельно: `poppler` (`poppler-utils` в
Debian/Ubuntu) и `qpdf`. `doctor` показывает недостающие пакеты и команды установки.
Встроенного LLM-runtime нет; Claude CLI не требуется.
Установка пакета не отправляет запросы к научным API.
`setup --check` явно включает проверку API после сохранения настроек.
Код возврата `doctor`: 0 — локальные зависимости доступны и запрошенные проверки
прошли; 1 — недостающие PDF-утилиты или ошибка запроса. Пропущенные API без ключей
показываются отдельно и не означают ошибку установки.

## Существующая библиотека

Структура `literature/<key>-W…/` + `research/` поддерживается на месте, без
`lumi init`, конфигурационного файла и миграции. Корень определяется из текущей
папки или любого её потомка. Явный путь: `lumi --project /path/to/project COMMAND`.

- `status`, `search`, `citations`, `add`, `parse`, `pages`, `lookup`, `show`, `check`
  и `library` работают с существующим `literature/`.
- `research/questions.md` задаёт вопросы; `research/field/` хранит журнал поиска,
  кандидатов и создаваемый командой `field` отчёт `FIELD.md`.
- `add` узнаёт имеющиеся статьи по ID, DOI и ключу, включая `core:…`, `lens:…` и `s2:…`.
  Старые 40-символьные Semantic Scholar ID также принимаются. Работы без DOI/OpenAlex
  получают папку `<key>-provider_<provider>_<id>`; исходная запись API сохраняется.
  Новые папки с OpenAlex ID получают имя `<key>-<id>`, обновляются `KEYS.tsv` и `INDEX.md`. Существующие README, заметки,
  оригиналы и уже извлечённый текст при повторном добавлении сохраняются.
- При явном `parse` используется `text_source_pdf` из метаданных; при его отсутствии —
  `paper.ocr.pdf`, затем `paper.refetch.pdf`, затем `paper.pdf`. Отсутствие явно
  выбранного файла — ошибка, без подмены другой версией. Это чтение готового OCR,
  не запуск нового распознавания.
- Ключ и наличие текста определяются при чтении старых метаданных без их массовой
  перезаписи. Без сохранённых печатных номеров используются номера PDF; для точной
  проверки передавайте `--pdf-page`, для настройки нумерации — `pages --first`.
- Единственный индекс Lumi — `literature/.lumi/index.sqlite`; он обновляется при изменении страниц.
  Старый `research/index.sqlite` и `research/knowledge/` не перезаписываются.
- Команды фактов/позиций, встроенные воркеры и `finish` удалены. Исследовательские
  записи в `research/knowledge/` сохраняются, движок их не читает и не меняет.
- Новый `init` создаёт эту же структуру и `.agents/skills/lumi-research/SKILL.md`.
  Старый `sources/papers/` не поддерживается и не мигрируется автоматически.
  Его файлы не удаляются.

`--library /path/to/library` явно выбирает библиотеку для команд `library`.
У `library check --project` прежний смысл: корень проверки устаревших ссылок;
глобальный `--project` ставится перед `library`.

## Объём поиска и результаты операций

`search --limit N` и `citations --limit N` используют положительный лимит вызывающего
агента, без общего потолка в 100 работ. Коннекторы получают несколько страниц;
цитирования показываются до N работ в каждом направлении. Для ранжирования исходящих
ссылок запрашиваются метаданные всех указанных OpenAlex ID, без прежнего среза в 200.
`lookup` и `library lookup` также соблюдают заданный лимит без скрытого усечения.

Ограничения API остаются явными: например, Semantic Scholar relevance search допускает
до 1000 результатов, а продолжение курсора OpenAlex требует API-ключа. При отказе,
исчерпании квоты или повторяющейся странице уже полученные результаты сохраняются;
вывод и журнал поиска показывают неполноту и причину. Курсор между запусками пока не
сохраняется. Завершение по `--limit` не доказывает исчерпание всех работ по теме.

Коды возврата основных поисковых операций и чтения:

- 0 — операция выполнена; для `add` доступен текст на всех сохранённых страницах.
- 1 — частичный результат или провал извлечения: например, сохранены метаданные без
  полного текста, часть страниц пуста, либо поиск оборвался на следующей странице.
  `check` также возвращает 1 для непрошедшей проверки цитаты.
- 2 — неверный вызов, недоступная конфигурация или ошибка, прервавшая операцию вне
  обработки частичного результата. `library check` сохраняет собственные коды диагностики.

`fulltext=partial` и `text_extraction=partial` означают, что некоторые страницы не имеют
текста. Номера хранятся в `empty_pdf_pages`; пустая страница может быть намеренной —
нужна проверка PDF. Статус `yes`/`ok` означает наличие текста на каждой странице,
но не подтверждает качество OCR или содержательное прочтение. Неполное повторное
извлечение сохраняет ранее записанный текст. OCR автоматически не запускается.

`lookup` ищет китайские фрагменты буквально внутри текста страниц, включая короткие
слова. В смешанном запросе совпадения объединяются с FTS-результатами без повторов
страниц. `--raw` сохраняет стандартный синтаксис и токенизацию SQLite FTS5.
